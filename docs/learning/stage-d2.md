# 阶段 D2 学习材料

> 先提交答案/命令，再给解答。

## 1. 知识定位

层级：**L2/L3 — 一致性备份、恢复验证、降级演练、容器安全、运行边界**。

本轮用到了：

- `mysqldump --single-transaction`
- gzip/sha256/600 权限
- 临时库恢复与逐表对账
- Flyway 版本校验
- Redis stop/BYPASS/start
- Nginx 安全头
- 非 root 容器
- `.env`/备份忽略

## 2. 一句话本质

D2 的本质不是“跑一次 mysqldump”，而是：**证明备份可恢复、降级可观察、安全边界可验证，并明确没有做到的部分。**

## 3. 阅读问题

1. `mysqldump --single-transaction` 为什么能减少备份不一致？它对 MyISAM/DDL 是否同样保证？
2. 为什么恢复演练必须用临时库，而不是直接覆盖当前库？覆盖前至少还要做什么？
3. 备份有 SHA256 和逐表 COUNT，为什么仍不能证明“可恢复”？
4. Redis 故障时菜单 200+BYPASS 与 503 的语义差别？什么时候应该 503？
5. Nginx 安全头、非 root、`.env` 忽略分别防什么？还缺哪些生产安全项？

## 4. 独立开发任务

**任务：备份轮转 + 加密 + 恢复耗时记录。**

要求：

- 按天/周保留策略；
- 备份加密（如 age/GPG）；
- 记录备份耗时、恢复耗时、行数；
- 失败清理半成品；
- 恢复演练输出 JSON；
- 不实现 PITR。

## 5. 故障定位练习

**场景**

备份文件 SHA256 校验通过，但恢复演练在 `orders` 表报外键错误；源库当前正常。

请排查：

1. 先查哪三个证据？
2. 如何区分“备份顺序/FK checks”“dump 中断”“schema 版本不匹配”“恢复目标非空”“字符集”？
3. 给出两条命令证据。
4. 修复应放在 dump 参数、恢复顺序、目标库初始化还是备份保留策略？

## 6. 脱稿口述题

用 90 秒解释：如何做一致性备份、如何证明恢复成功、Redis 挂了菜单为什么还能开、当前运行边界是什么。

要求：

- 提到 single-transaction、临时库、逐表对账、BYPASS、非 root；
- 明确没有 PITR/异地副本；
- 不照读脚本。
