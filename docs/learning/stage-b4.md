# 阶段 B4 学习材料

> 先提交 SQL/代码/分析，再给答案。

## 1. 知识定位

层级：**L2/L3 — 批量事务、全有或全无、幂等键、请求哈希、唯一键竞争、REPEATABLE READ 当前读、审计**。

本轮用到了：

- 1–100 行批次
- 全有或全无事务
- 幂等键 + SHA-256 请求哈希
- 唯一键插入竞争
- `SELECT ... FOR UPDATE`
- 逐行库存条件更新
- ADJUST 流水与批次审计
- 文本批量输入 UI

## 2. 一句话本质

B4 的本质不是“循环调用单行调整”，而是：**一批操作必须共享一个事务和幂等身份；任何一行失败都不能留下半批状态，重复请求不能重复扣库存。**

## 3. 阅读问题

1. 为什么批次内一行失败要回滚全部？如果允许部分成功，响应、重试和库存审计会复杂在哪里？
2. 幂等键为什么必须是 `(admin_user_id, key)` 作用域？如果只按 key 全局唯一，会发生什么？
3. 请求哈希为什么要包含 reason 与排序后的 productId？同 key 同库存变化但不同原因算不算同一请求？
4. 同键并发时，第二个请求在唯一键冲突后为什么必须用 `FOR UPDATE` 重读？普通 SELECT 在 REPEATABLE READ 下可能看到什么？
5. 批次行为什么按 productId 排序？与多商品订单的固定锁顺序有什么相同目的？

## 4. 独立开发任务

**任务：CSV 批量导入 dry-run 与逐行校验。**

要求：

- 上传/粘贴 CSV；
- dry-run 只校验不写库存；
- 返回每行错误与汇总；
- 正式执行仍全有或全无；
- 同一 Idempotency-Key 重放 dry-run/执行结果；
- 限制行数/文件大小；
- 补权限、重复键、失败回滚、并发测试。

不实现异步任务。

## 5. 故障定位练习

**场景**

管理员重试同一批次，库存被扣了两次；数据库有两条不同 batch，但请求体完全一样。请排查：

1. 先查哪三个证据？
2. 如何区分“每次生成新 key”“key 全局作用域错误”“唯一约束没生效”“重试发生在另一管理员”“前端重发时 body 变化”？
3. 给出两条 SQL 证据。
4. 修复应放在前端、幂等键作用域、数据库唯一键还是事务？
