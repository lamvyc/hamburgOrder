# 阶段 D3 学习材料

> 先提交答案/命令，再给解答。

## 1. 知识定位

层级：**L2/L3 — 负载基线、延迟分位数、缓存命中、发布门禁、容量边界**。

本轮用到了：

- 并发 worker pool
- 预热与 P50/P95/P99
- 吞吐 vs 延迟
- X-Cache 分布
- 发布检查聚合
- 测试/镜像/备份/安全门禁

## 2. 一句话本质

D3 的本质不是“跑个压测数字”，而是：**用可复现的基线判断系统在当前环境下的表现，并明确它不能证明什么。**

## 3. 阅读问题

1. 平均延迟为什么不够？P95/P99 分别暴露什么？
2. 并发从 1 提到 20，吞吐上升但 P95 也上升，如何判断瓶颈？
3. 菜单请求 204 个 HIT / 1 个 MISS，能说明缓存策略一定好吗？
4. 发布检查里为什么同时需要测试计数、镜像 ID、备份、健康和安全头？
5. 本地 Colima/单机容器的基线为什么不能直接作为生产 SLA？

## 4. 独立开发任务

**任务：写 5xx/超时/长尾报告与 soak 草案。**

要求：

- 区分 4xx 与 5xx；
- 记录超时阈值与重试；
- 5 分钟 soak；
- 输出 P95/P99 与错误率；
- 给出可接受/不可接受判断；
- 不写生产 SLA。

## 5. 故障定位练习

**场景**

菜单负载 P95 从 30ms 升到 800ms，错误为 0；Redis CPU 正常，MySQL QPS 上升 20 倍。请排查缓存是否失效/穿透、single-flight 是否失效、请求是否绕过缓存、连接池/慢查询，并给出两条指标证据。

## 6. 脱稿口述题

用 90 秒解释：如何做可复现基线、为什么看 P95、缓存命中如何影响结果、发布检查应包含什么、当前基线不能证明什么。

要求：

- 提到并发、分位数、X-Cache、门禁、边界；
- 不照读脚本。
