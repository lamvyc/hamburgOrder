## 2. 一句话本质

B1 的本质不是“减 5 元”，而是：**优惠券是有状态、有限量、有归属的资源；领取、锁定、核销、释放都必须由数据库条件和事务决定，前端只展示结果。**

## 3. 阅读问题

1. 领取优惠券为什么要同时做“模板 claimed_quantity 条件自增”和“用户券唯一键”？只做其中一个会怎样？
2. 同用户并发领取两张券，唯一键冲突后为什么 claimed_quantity 不能留下 +1？事务回滚覆盖了哪些语句？
3. 下单时为什么先校验券、插入订单、再条件锁券？两个订单用同一张券，失败方为什么不能留下订单或库存预占？
4. 支付核销、取消释放、超时释放分别如何写条件 UPDATE？为什么都要求 affected rows=1？
5. 订单 total_amount 与 discount_amount 的关系是什么？如果客户端传入优惠金额，会有什么风险？

## 4. 独立开发任务

**任务：新增“百分比优惠券”，支持封顶与金额舍入。**

要求：

- `discount_type` 支持 FIXED / PERCENT；
- PERCENT 配置 `discount_rate`（如 0.15）与 `max_discount`；
- 优惠 = min(商品小计 × rate, max_discount, 商品小计)；
- 使用 `BigDecimal`，明确舍入模式与到分规则；
- 保持固定金额券行为不变；
- 领取/锁券/核销/释放状态机不变；
- 补边界测试：0 元、1 分、封顶、最小门槛、重复使用；
- 不实现多券叠加。

先写测试与金额表，再改 schema/service。
